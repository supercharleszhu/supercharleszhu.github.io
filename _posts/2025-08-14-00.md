## Introduction

This post derives scaled dot-product attention, turns stable softmax into an
online recurrence, and implements the same one-pass forward algorithm in
Triton and CuTe DSL without materializing the full attention matrix.

The complete executable lesson is available in
[Day 12 of the CuTe DSL curriculum](https://github.com/supercharleszhu/mlinfra-puzzle/blob/main/gpu-programming-puzzle/cute-dsl/day12_softmax_attention/day12.ipynb).
The standalone implementation is in
[`solution.py`](https://github.com/supercharleszhu/mlinfra-puzzle/blob/main/gpu-programming-puzzle/cute-dsl/day12_softmax_attention/solution.py).

The goal is not to reproduce every production FlashAttention-2 optimization.
Instead, the focus is the algorithmic core:

```text
Q-row ownership
    -> stream K/V tiles
    -> update online (m, l, U) state
    -> normalize once
    -> never write the N x N score matrix to HBM
```

## 1. What softmax attention computes

For one batch-head, let:

- `Q` have shape `(N_q, D)`;
- `K` and `V` have shape `(N_k, D)`;
- `D` be the head dimension.

Scaled dot-product attention is:

$$
S = \frac{QK^T}{\sqrt{D}},
\qquad
P_{ij} =
\frac{\exp(S_{ij})}
{\sum_{r=0}^{N_k-1}\exp(S_{ir})},
\qquad
O = PV.
$$

Each query row compares with every key row. Softmax converts the scores into
positive weights that sum to one, and the output is a weighted combination of
the value rows.

### Stable softmax

The numerically stable form subtracts each score row's maximum:

$$
m_i = \max_j S_{ij},
\qquad
P_{ij} =
\frac{\exp(S_{ij}-m_i)}
{\sum_r \exp(S_{ir}-m_i)}.
$$

Subtracting the maximum does not change the result because the same factor
$e^{-m_i}$ appears in every numerator and in the denominator. It prevents
large positive scores from overflowing `exp`.

## 2. Why ordinary attention is memory-hungry

A direct implementation commonly creates:

```text
scores        = Q @ K.T       # N_q x N_k
probabilities = softmax(...)  # N_q x N_k
output        = probabilities @ V
```

When `N_q = N_k = N`, the score and probability matrices contain `N^2`
elements even though the final output contains only `N * D`. Writing and
rereading those quadratic intermediates from HBM is the main problem
FlashAttention removes.

FlashAttention keeps only a small score tile on chip:

```text
one Q row/block
    for each K/V tile:
        score tile = Q tile @ K tile.T
        update online softmax state
        update output accumulator with V tile
    normalize once and store O
```

The complete `N x N` matrix is never stored in HBM.

## 3. The one-pass softmax attention equation

For one query row, maintain three values after processing some K/V tiles:

$$
m = \max_{\text{processed }j} s_j,
$$

$$
\ell = \sum_{\text{processed }j} e^{s_j-m},
$$

$$
U = \sum_{\text{processed }j} e^{s_j-m}v_j.
$$

`U` is deliberately **unnormalized**. The current attention output would be
`U / l`, but FlashAttention-2 delays that division until all tiles have been
processed.

For a new score tile $S_t$ and matching value tile $V_t$, compute:

$$
\widetilde{m}_t = \operatorname{rowmax}(S_t),
\qquad
m' = \max(m, \widetilde{m}_t),
$$

$$
\alpha = e^{m-m'},
\qquad
P_t = e^{S_t-m'},
$$

$$
\ell' = \alpha\ell + \operatorname{rowsum}(P_t),
$$

$$
U' = \alpha U + P_tV_t.
$$

After the final tile:

$$
O = \frac{U}{\ell}.
$$

These updates preserve the invariant:

$$
\ell' = \sum_{\text{all processed }j}e^{s_j-m'},
\qquad
U' = \sum_{\text{all processed }j}e^{s_j-m'}v_j.
$$

The factor `alpha` rescales every old term from the old maximum to the new
maximum. This is why the algorithm remains stable even when a later tile
contains a much larger score.

### Verify the recurrence before writing a kernel

```python
import math
import torch


def online_attention_reference(q, k, v, key_tile=16):
    scale = 1.0 / math.sqrt(q.shape[-1])
    running_max = torch.tensor(
        -torch.inf, device=q.device, dtype=torch.float32
    )
    running_sum = torch.tensor(
        0.0, device=q.device, dtype=torch.float32
    )
    output_accumulator = torch.zeros_like(q)

    for start in range(0, k.shape[0], key_tile):
        k_tile = k[start : start + key_tile]
        v_tile = v[start : start + key_tile]
        scores = (k_tile @ q) * scale

        new_max = torch.maximum(running_max, scores.max())
        previous_scale = torch.exp(running_max - new_max)
        probabilities = torch.exp(scores - new_max)

        running_sum = (
            running_sum * previous_scale + probabilities.sum()
        )
        output_accumulator = (
            output_accumulator * previous_scale
            + probabilities @ v_tile
        )
        running_max = new_max

    return output_accumulator / running_sum
```

For any key-tile size, this produces the same result as:

```python
direct = torch.softmax(
    k @ q / math.sqrt(q.shape[-1]), dim=0
) @ v
```

## 4. What FlashAttention-2 changes

FlashAttention-1 already introduced tiling and online softmax.
FlashAttention-2 improves the work assignment and removes unnecessary
non-matmul operations.

### 4.1 Delay output normalization

The normalized FA1 recurrence can be written as:

$$
O' =
\frac{\alpha\ell}{\ell'}O
+ \frac{P_tV_t}{\ell'}.
$$

FA2 instead accumulates the unnormalized `U`:

$$
U' = \alpha U + P_tV_t,
$$

and performs `O = U / l` once at the end. This avoids repeatedly dividing and
rescaling every output element.

### 4.2 Assign each Q block to one CTA

The outer parallel dimension is the Q sequence:

```text
CTA 0 owns Q rows   0..Br-1
CTA 1 owns Q rows  Br..2Br-1
...
```

Each CTA loops over all K/V tiles and exclusively owns its output tile. The
forward pass therefore needs no atomic accumulation.

### 4.3 Partition warps only along Q rows

FA2 stacks warps along Q rows rather than splitting a softmax row across the
K-column dimension:

```text
CTA query block
├── warp 0 -> complete softmax rows
├── warp 1 -> complete softmax rows
├── warp 2 -> complete softmax rows
└── warp 3 -> complete softmax rows
```

Each warp sees the complete K-column extent for its Q rows, avoiding
cross-warp communication for the softmax reduction.

Production kernels additionally use tensor-core MMA, swizzled shared memory,
asynchronous K/V pipelines, FP16/BF16 inputs, causal masks, dropout, and a
specialized backward pass. The implementations below isolate the forward
algorithm first.

## 5. Correctness and benchmark contract

Both kernels use contiguous FP32 tensors with shape:

```text
[batch_heads, sequence_length, head_dim]
```

The direct reference materializes the score matrix only for testing:

```python
def attention_reference(q, k, v):
    scale = 1.0 / math.sqrt(q.shape[-1])
    scores = torch.matmul(q, k.transpose(-1, -2)) * scale
    return torch.matmul(torch.softmax(scores, dim=-1), v)
```

Correctness tests use:

```python
TEST_SHAPES = (
    (2, 17, 32),
    (3, 33, 64),
    (4, 64, 64),
)
```

Lengths 17 and 33 deliberately exercise partial key tiles and partially
populated Q blocks.

Each benchmark:

- checks correctness before timing;
- reuses compiled callables;
- uses `triton.testing.do_bench`;
- reports the two attention matmuls:

$$
\text{FLOPs} \approx 4 B_h N^2 D.
$$

The count omits exponentials, reductions, and rescaling, so TFLOP/s is an
attention convention rather than a complete instruction count.

## 6. Implementations

Both implementations apply the same `(m, l, U)` invariant. Triton updates it
for a 16-key tile; CuTe shows the scalar-key special case.

### 6.1 Triton implementation

One Triton program owns one query row. It loads Q once and processes 16 keys
at a time:

```text
scores = K_tile @ q / sqrt(D)
m_new = max(m, max(scores))
alpha = exp(m - m_new)
p = exp(scores - m_new)
l = alpha * l + sum(p)
U = alpha * U + sum(p[:, None] * V_tile, axis=0)
m = m_new
```

`U` is a `BLOCK_D` FP32 vector. `scores` and `p` contain only `BLOCK_N`
values, so the kernel never creates an `N x N` output.

```python
import triton
import triton.language as tl


@triton.jit
def triton_flash_attention2_kernel(
    q_ptr,
    k_ptr,
    v_ptr,
    o_ptr,
    softmax_scale,
    N_CTX: tl.constexpr,
    HEAD_DIM: tl.constexpr,
    BLOCK_N: tl.constexpr,
    BLOCK_D: tl.constexpr,
):
    program = tl.program_id(0)
    batch_head = program // N_CTX
    query_idx = program % N_CTX

    dimensions = tl.arange(0, BLOCK_D)
    dimension_mask = dimensions < HEAD_DIM
    tensor_base = batch_head * N_CTX * HEAD_DIM
    q_offsets = tensor_base + query_idx * HEAD_DIM + dimensions
    q = tl.load(
        q_ptr + q_offsets,
        mask=dimension_mask,
        other=0.0,
    )

    running_max = -float("inf")
    running_sum = 0.0
    output_accumulator = tl.zeros(
        (BLOCK_D,), dtype=tl.float32
    )

    for key_start in range(0, N_CTX, BLOCK_N):
        key_indices = key_start + tl.arange(0, BLOCK_N)
        key_mask = key_indices < N_CTX
        kv_offsets = (
            tensor_base
            + key_indices[:, None] * HEAD_DIM
            + dimensions[None, :]
        )

        keys = tl.load(
            k_ptr + kv_offsets,
            mask=key_mask[:, None] & dimension_mask[None, :],
            other=0.0,
        )
        scores = (
            tl.sum(keys * q[None, :], axis=1)
            * softmax_scale
        )
        scores = tl.where(
            key_mask, scores, -float("inf")
        )

        tile_max = tl.max(scores, axis=0)
        new_max = tl.maximum(running_max, tile_max)
        previous_scale = tl.exp(running_max - new_max)
        probabilities = tl.exp(scores - new_max)
        tile_sum = tl.sum(probabilities, axis=0)

        values = tl.load(
            v_ptr + kv_offsets,
            mask=key_mask[:, None] & dimension_mask[None, :],
            other=0.0,
        )
        output_accumulator = (
            output_accumulator * previous_scale
            + tl.sum(
                probabilities[:, None] * values,
                axis=0,
            )
        )
        running_sum = (
            running_sum * previous_scale + tile_sum
        )
        running_max = new_max

    tl.store(
        o_ptr + q_offsets,
        output_accumulator / running_sum,
        mask=dimension_mask,
    )
```

The launcher specializes sequence length, head dimension, and tile sizes:

```python
def launch_triton_attention(q, k, v, output):
    batch_heads, sequence_length, head_dim = q.shape
    block_d = triton.next_power_of_2(head_dim)

    triton_flash_attention2_kernel[
        (batch_heads * sequence_length,)
    ](
        q,
        k,
        v,
        output,
        1.0 / math.sqrt(head_dim),
        N_CTX=sequence_length,
        HEAD_DIM=head_dim,
        BLOCK_N=16,
        BLOCK_D=block_d,
        num_warps=4,
    )
```

### 6.2 CuTe DSL implementation

The CuTe kernel launches four warps per CTA:

```text
CTA query block
├── warp 0 -> one complete Q row
├── warp 1 -> one complete Q row
├── warp 2 -> one complete Q row
└── warp 3 -> one complete Q row
```

Every warp iterates over every key. Lanes divide the head dimension as
`lane, lane + 32, ...`; a five-step shuffle reduction combines each dot
product. Each lane owns the matching output dimensions in registers.

For clarity, this implementation uses a K/V tile size of one:

$$
\widetilde{m}_t = s_t,
\qquad
P_t = e^{s_t-m'}.
$$

This is the `B_c = 1` special case of the same recurrence used by Triton's
16-key tile.

```python
import cutlass
import cutlass.cute as cute
from cutlass.cute.runtime import from_dlpack

WARP_SIZE = 32
WARPS_PER_CTA = 4


def warp_reduce_sum(value: cutlass.Float32):
    for offset in (16, 8, 4, 2, 1):
        value += cute.arch.shuffle_sync_bfly(
            value,
            offset=offset,
            mask=-1,
            mask_and_clamp=31,
        )
    return value


class SimplifiedFlashAttention2:
    def __init__(
        self,
        batch_heads,
        sequence_length,
        head_dim,
    ):
        self.batch_heads = batch_heads
        self.sequence_length = sequence_length
        self.head_dim = head_dim
        self.values_per_lane = (
            head_dim + WARP_SIZE - 1
        ) // WARP_SIZE
        self.softmax_scale = 1.0 / math.sqrt(head_dim)

    @cute.jit
    def __call__(
        self,
        q: cute.Tensor,
        k: cute.Tensor,
        v: cute.Tensor,
        output: cute.Tensor,
    ):
        self.kernel(q, k, v, output).launch(
            grid=(
                cute.ceil_div(
                    self.sequence_length,
                    WARPS_PER_CTA,
                ),
                self.batch_heads,
                1,
            ),
            block=(
                WARP_SIZE * WARPS_PER_CTA,
                1,
                1,
            ),
        )

    @cute.kernel
    def kernel(
        self,
        q: cute.Tensor,
        k: cute.Tensor,
        v: cute.Tensor,
        output: cute.Tensor,
    ):
        thread_idx, _, _ = cute.arch.thread_idx()
        query_block, batch_head, _ = (
            cute.arch.block_idx()
        )
        warp_idx = thread_idx // WARP_SIZE
        lane = thread_idx % WARP_SIZE
        query_idx = (
            query_block * WARPS_PER_CTA + warp_idx
        )

        q_values = cute.make_rmem_tensor(
            (self.values_per_lane,),
            cutlass.Float32,
        )
        output_accumulator = cute.make_rmem_tensor(
            (self.values_per_lane,),
            cutlass.Float32,
        )
        q_values.fill(0.0)
        output_accumulator.fill(0.0)

        if query_idx < self.sequence_length:
            for item in cutlass.range_constexpr(
                self.values_per_lane
            ):
                dimension = lane + item * WARP_SIZE
                if dimension < self.head_dim:
                    q_values[item] = q[
                        batch_head,
                        query_idx,
                        dimension,
                    ]

            running_max = -cutlass.Float32.inf
            running_sum = cutlass.Float32.zero

            for key_idx in cutlass.range(
                self.sequence_length
            ):
                partial_score = cutlass.Float32.zero

                for item in cutlass.range_constexpr(
                    self.values_per_lane
                ):
                    dimension = lane + item * WARP_SIZE
                    if dimension < self.head_dim:
                        partial_score += (
                            q_values[item]
                            * k[
                                batch_head,
                                key_idx,
                                dimension,
                            ]
                        )

                score = (
                    warp_reduce_sum(partial_score)
                    * self.softmax_scale
                )
                new_max = cute.arch.fmax(
                    running_max, score
                )
                previous_scale = cute.math.exp(
                    running_max - new_max
                )
                probability = cute.math.exp(
                    score - new_max
                )
                running_sum = (
                    running_sum * previous_scale
                    + probability
                )

                for item in cutlass.range_constexpr(
                    self.values_per_lane
                ):
                    dimension = lane + item * WARP_SIZE
                    if dimension < self.head_dim:
                        output_accumulator[item] = (
                            output_accumulator[item]
                            * previous_scale
                            + probability
                            * v[
                                batch_head,
                                key_idx,
                                dimension,
                            ]
                        )

                running_max = new_max

            for item in cutlass.range_constexpr(
                self.values_per_lane
            ):
                dimension = lane + item * WARP_SIZE
                if dimension < self.head_dim:
                    output[
                        batch_head,
                        query_idx,
                        dimension,
                    ] = (
                        output_accumulator[item]
                        / running_sum
                    )
```

The host wrapper converts PyTorch tensors with DLPack and compiles a kernel
specialized for the input shape:

```python
def prepare_cute_attention(q, k, v):
    output = torch.empty_like(q)
    q_cute = from_dlpack(q, assumed_align=16)
    k_cute = from_dlpack(k, assumed_align=16)
    v_cute = from_dlpack(v, assumed_align=16)
    output_cute = from_dlpack(
        output, assumed_align=16
    )

    compiled = cute.compile(
        SimplifiedFlashAttention2(*q.shape),
        q_cute,
        k_cute,
        v_cute,
        output_cute,
    )
    return output, compiled, (
        q_cute,
        k_cute,
        v_cute,
        output_cute,
    )
```

## 7. Comparing the implementations

| Property | Triton | CuTe DSL |
| --- | --- | --- |
| Q ownership | One program per Q row | Four Q-row warps per CTA |
| K/V update size | 16 keys | One key |
| Dot product | Triton vector reduction | Lane FMAs plus warp shuffles |
| Output state | `BLOCK_D` FP32 vector | Per-lane FP32 register fragment |
| Output normalization | Once after K/V loop | Once after K/V loop |
| Score matrix in HBM | Never | Never |
| Tensor cores | No | No |
| Shared K/V staging | No | No |

The key result is not which educational kernel wins this small benchmark.
Both implementations have already removed the defining quadratic
intermediate and both implement exactly the same stable online recurrence.

The main difference is how ownership is expressed:

- Triton describes logical vectors and reductions; the compiler chooses the
  lane mapping.
- CuTe explicitly maps Q rows to warps, head dimensions to lanes, and output
  dimensions to register fragments.

## 8. Next optimization steps

The next version should preserve the exact `(m, l, U)` equations while
replacing one mechanism at a time:

1. Stage K/V tiles in shared memory so the four CuTe warps reuse them.
2. Process multiple keys per CuTe recurrence update.
3. Replace scalar score and value products with FP16/BF16 `TiledMma`.
4. Add causal and uneven-length masks.
5. Pipeline global-to-shared copies with current-tile compute.
6. Store logsumexp and implement backward recomputation.
7. Use TMA/WGMMA on H100 or TMA/`tcgen05.mma` plus TMEM on B300.

Production FlashAttention-2 combines all of these with architecture-specific
tile sizes, register-pressure control, and carefully overlapped memory
movement. The one-pass recurrence stays the same.
